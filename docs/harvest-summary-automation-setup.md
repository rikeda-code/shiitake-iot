# 収穫実績集計表 新規タブ自動追加 セットアップ手順

対象スプレッドシートの集計タブで、号機ごとのタブ(例:「16(7/13)L3」)を
新規追加すると、自動で以下を行います。

1. 3行目(見本行)の下に1行追加
2. 3行目にある関数(A~Q列)と同じ関数を追加された4行目に展開
3. 追加された4行目のF列に新規タブ名を記入

逆に、追加済みのタブが削除された場合は、対応する集計行も自動的に削除します。

## 対象スプレッドシート一覧

| スプレッドシート | 集計タブ名 | 実データの先頭行 | 貼り付けるファイル |
| --- | --- | --- | --- |
| 号機別収穫実績集計表(いなべ) | 収穫実績集計表1 | 4行目 | `dashboard/harvest-summary-automation.gs` |
| 26/群馬担当号機収穫管理 | 収穫実績集計表 | 4行目 | `dashboard/harvest-summary-automation-gunma.gs` |
| 26/南丹担当号機収穫管理 | 収穫実績集計表 | 4行目 | `dashboard/harvest-summary-automation-nantan.gs` |

以下の手順は、上の表から対象のスプレッドシートに対応するファイルに
読み替えて進めてください。3つとも同じ仕組みですが、シート名や
除外タブ・命名パターンが少しずつ違うため、ファイルを分けています。

## 前提: 既存のApps Scriptコードを確認する

このスプレッドシートに既に他のApps Scriptコードが入っている場合、
上書きすると既存の自動化が壊れる可能性があります。まず「拡張機能」→
「Apps Script」を開き、既存コードの有無を確認してください。

- 何も書かれていない場合 → そのまま貼り付けてOK
- 既存コードがある場合 → 既存コードは残したまま、対象ファイルの中身を
  その下に追記してください(Claude Codeに「このスプレッドシートの
  Apps Scriptに追記して」と伝えれば確認しながら進められます)

## 手順

1. 対象のスプレッドシートを開く(上の表を参照)
2. メニュー「拡張機能」→「Apps Script」を開く
3. リポジトリの対象ファイル(`dashboard/harvest-summary-automation.gs` /
   `dashboard/harvest-summary-automation-gunma.gs` /
   `dashboard/harvest-summary-automation-nantan.gs`)の中身を貼り付けて保存する
4. 関数選択のプルダウンから `createOnChangeTrigger` を選び、実行ボタン(▶)をクリック
   - 初回は権限の承認を求められるので許可する
   - これでタブの追加・削除・リネームを検知するトリガーが1回だけ登録されます(再実行しても重複登録はされません)
   - **重要**: この実行時点の「現在のタブ一覧」を基準(以降の追加・削除判定の元)として記録します。
     つまり、この時点で既に存在するタブは、集計表に行が無くても「新しく追加されたタブ」とは
     見なされず、自動追加の対象になりません。既存タブをまとめて追加したい場合は、このスクリプトではなく
     手動(コピー&ペーストなど)で対応してください。集計表を大きく編集した直後は、基準をずらさないためにも
     `createOnChangeTrigger` を実行し直しておくと安全です
5. スプレッドシートを再読み込みすると、メニューバーに「収穫実績集計 自動化」が追加されます
6. メニュー「収穫実績集計 自動化」→「設定を確認」を実行し、「OK」と表示されることを確認する
   - 「シートが見つかりません」と表示された場合は、スクリプト冒頭の `SUMMARY_SHEET_NAME` が
     実際のタブ名と一致していません。表示された現在のタブ一覧を見て、正しい名前に書き換えてください
     (タブ名は見た目だけでは末尾の数字などが分かりにくいことがあるため、必ずこの手順で確認してください)

## 使い方

### タブを追加したとき

1. いつも通り、新しいロットのタブを手動で追加する(例: 既存タブをコピーして
   リネーム、または「+」で新規タブを作成してリネーム)
2. タブ名を確定させた時点(リネームが完了した瞬間)で自動的に
   集計タブの3行目の下に1行追加され、関数が展開され、
   F列に新しいタブ名が入ります
3. 自動で反映されない場合は、対象タブを開いた状態でメニュー
   「収穫実績集計 自動化」→「今開いているタブを集計表に追加」を実行してください
   (既に追加済みのタブは二重に追加されないようになっています)

### タブを削除したとき(誤って追加したタブを消したときなど)

1. 集計表に載っているロットタブを、右クリック→「削除」で削除する
2. 削除すると自動的に、集計タブの中からF列がそのタブ名と一致する行が
   検索され、削除されます(該当行が複数あれば全て削除されます)
3. 自動で消えない場合は、メニュー「収穫実績集計 自動化」→
   「指定した名前の行を集計表から削除」を実行し、削除したタブ名を
   入力してください(例:「16(7/13)L3」)
4. この削除検知は「前回覚えていたタブ一覧」と「現在のタブ一覧」を比較する
   仕組みのため、`createOnChangeTrigger` を実行し直した直後の1回目の削除だけは
   検知できない場合があります(2回目以降は正常に動作します)。その場合も
   上記3の手動フォールバックで削除できます

## 注意点

- 行が追加されるのは、タブ名がロットタブの命名パターン(`LOT_NAME_PATTERN`)に
  一致する場合のみです。「token」「test」「17pp」「15（池田）」のような
  管理用・個人用・テスト用のタブは、この形式に一致しないため自動的に対象外になります
  - いなべ版: `号機番号(月/日)◯◯L数字`(例:「16(7/13)L3」「32(6/29)6志摩L3」)
  - 群馬版・南丹版: `号機番号(ハイフン可)(月/日)◯◯L数字`(例:「17(7/22)L3」
    「3-17(7/19)L3」「3-8(6/29)志摩L3」)
- 上記パターンに一致してしまうがロットタブではないタブ名がある場合は、
  対象ファイル内の `EXCLUDED_SHEET_NAMES` にそのタブ名を追記してください
- シートを複製した直後の仮の名前(「◯◯のコピー」「シート2」など)は無視され、
  リネームして最終的なタブ名が確定した時点で処理されます
- 3行目(見本行)の関数自体は変更していません。現在3行目に `#REF!` などの
  エラーが出ている場合、そのまま4行目にも展開されるため、必要であれば
  3行目の関数を別途修正してください(いなべ・群馬・南丹いずれの集計タブも、
  現時点で3行目は `#REF!` になっています)
- メニューの「収穫実績集計 自動化」→「今開いているタブを集計表に追加」/
  「指定した名前の行を集計表から削除」はどちらも手動フォールバックのため、
  上記の命名パターンに一致しないタブ名でも実行できます
  (意図的に例外的な追加・削除をしたい場合のみ使用してください)

## 既に追加されてしまった不要な行を削除する(いなべ版で発生した問題)

いなべ版の初期バージョンでは除外リスト(ブラックリスト)方式だったため、
「token」「test」「15（池田）」のようなロットタブではないタブの行も
集計タブに追加されてしまっていました。不要な行が残っている場合は
以下の手順で削除してください(この節はいなべ版のみ該当。群馬版は
最初からホワイトリスト方式で導入するため発生しません)。

1. 集計タブでF列を確認し、ロット名として不自然な行
   (「token」「test」「17pp」「群馬管理原本」「シート名リスト」
   「月稼働コンテナ内」「収穫実績集計表」「◯（池田）」「◯（小林）」など)を探す
2. 該当する行番号を左端でクリック(複数ある場合はCtrlキーを押しながら追加でクリック)
3. 選択した行番号の上で右クリック→「選択した行を削除」
4. 更新後のスクリプトを再度貼り付け・保存しておけば、今後は同じ問題は起きません

## 南丹版で発生した問題(シート名の思い違い)

導入時、南丹の集計タブ名が「収穫実績集計表」か「収穫実績集計表1」かで一時的に
混乱がありましたが、`checkSetup`(メニューの「設定を確認」)で実際に確認した結果、
正しくは「**収穫実績集計表**」(末尾に1なし)でした。`SUMMARY_SHEET_NAME` が
一致しないと、スクリプトはエラーも出さずに何もしないため、原因の切り分けに
時間がかかりました。

また、導入作業の途中では南丹だけ3行目(見本行)と実データの間に4行目が空白の
区切り行として存在していた時期があり、一時的に `DATA_START_ROW = 5` としていましたが、
その後この空白行が無くなり、いなべ・群馬と同じく4行目からデータが始まる構造に
戻ったため、`DATA_START_ROW = 4` に直しています。

タブ名の思い違いにすぐ気づけるよう、メニューに「設定を確認」を追加しました。
導入時は必ずこれを実行し、「OK」と表示されることを確認してください。
「シートが見つかりません」という表示が出た場合は、表示された現在のタブ一覧を見て
`SUMMARY_SHEET_NAME` を実際のタブ名と完全に一致するよう書き換えてください。

## 南丹版で発生した問題(過去分タブの一括追加)

シート名を修正した直後、「今回新しく追加したタブかどうか」を「集計表のF列に
まだ名前が載っていないか」だけで判定していたため、過去に何らかの理由で
集計表に載っていなかった大量の古いタブまで「未追加」と誤認識され、一気に
まとめて追加されてしまう不具合がありました。

これを修正し、「前回 `createOnChangeTrigger` を実行した(または前回イベントが
発生した)時点で存在していたタブかどうか」を基準にするようにしました。この
基準より前から存在するタブは、集計表に行が無くても自動追加の対象にはなりません。
自動追加されるのは、その基準より後に名前が確定した本当に新しいタブだけです。

この修正に伴い、集計表を手動で整理した(誤って追加された行を削除した)直後は、
必ず `createOnChangeTrigger` を再実行して基準を最新の状態に更新し直してください。

## タブ数が多いスプレッドシートでの一時的なエラーについて

南丹のスプレッドシートはタブ数が非常に多く(70以上)、相互参照の関数も多いため、
`createOnChangeTrigger` の実行時などに `Service Spreadsheets failed while
accessing document with id ...` という一時的なエラーが出ることがあります。
これはGoogle側の負荷・タイムアウトによるものでコードの不具合ではないため、
全スクリプトに自動リトライ(数秒待って最大3回まで再試行)を組み込みました。
それでも失敗する場合は、時間をおいて(他の人がそのシートを編集していない
タイミングで)もう一度実行してみてください。
